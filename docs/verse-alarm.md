# Arise O Sleeper!

Open **Arise O Sleeper!** from its own launcher icon. The alarm is built by the `ariseosleeper` module with application ID `com.example.ariseosleeper`; Install Lock no longer contains its screens, scheduler, audio service, or verse storage code.

The apps have separate private storage. Existing Install Lock alarm times, passages, and progress are not automatically migrated. Complete any active routine and turn off the integrated alarms before updating Install Lock, then set up the new app separately. The pre-extraction code is preserved on GitHub in commit `ed0dee4`.

1. Under **Your ESV passages**, enter a reference and plain ESV passage text without verse numbers, then tap **Add passage**. This form appears above the saved passage list, even when the daily alarm is enabled. During an active routine it remains visible but disabled until all checks are finished. No Bible text is bundled or fetched.
2. Grant alarms/reminders, notifications and full-screen alarm access. Raise the alarm volume, test the sound, and try dictation in Practice.
3. Choose one or more daily local times with **Add alarm** (up to 24 different times), set **Number of sessions per alarm** (default 3; range 1-20), and choose the number of successful completions before memory mode (default 3; range 2–20). Enable and save.

Each daily alarm begins a routine with your chosen number of sessions (verse checks), with a warning one minute before its scheduled ringing time. Each follow-up alarm is scheduled five minutes after the previous check is completed, and also has a one-minute warning. During the warning, a single notification chime sounds and the verse-entry page is presented. Completing the verse during that minute counts as the check and prevents that alarm from ringing. Earlier submissions are rejected. If unfinished, the normal alarm rings at its original deadline, preserving typed text and dictation results. New passages are visible. Learned passages display only their reference and must be entered from memory. Selection alternates between learning and memory passages when both are available, rotating by least recently completed within each group.

Warning delivery is persisted once per check; refreshes and duplicate broadcasts cannot repeatedly chime. A separate notification channel uses the phone's default notification sound and obeys notification sound/DND settings. The standalone app relies on Android's full-screen notification behavior or the notification tap to open the warning page. If a restart or delayed broadcast reaches the last minute late, only the remaining entry time is available. The real alarm has its own scheduled event so a missed warning does not postpone it. The alarm-volume hold begins with the first warning and continues until all checks finish.

Each successful alarm challenge earns one completion for its passage. Practice does not earn completions. Incorrect or duplicate submissions earn no credit. Memory mode is fixed when a challenge is selected; it cannot change partway through entry.

Alarm volume is held at its level when the wake-up routine starts, through all checks, quiet periods and follow-up waits. If that level is zero, the minimum audible level is used. The held level survives process restarts and reboot, and is released after the final check. Volume keys are consumed on the alarm screen. Elsewhere, a settings observer and 250 ms polling restore attempts to change the alarm stream; a slider may briefly move before restoration. Call and media volume are not changed. Android's `DISALLOW_ADJUST_VOLUME` restriction is deliberately avoided because it also mutes the device. Actual timing and manufacturer behavior require phone testing.

Typing ignores case, whitespace and punctuation. Dictation uses Android's speech-recognition activity; short passages still require every word, while longer dictated passages allow one word error per 20 words, capped at three. Dictated text can be reviewed and corrected before submission. Keyboard dictation is also usable, with the same exact word matching as typing. The configured speech provider may use the network. A missing speech provider does not prevent typing.

Verse answers, practice answers and library text use visible-password input with no dictionary suggestions or autocorrect, plus the no-personalized-learning keyboard flag. Text remains readable. Autofill, content capture and smart text classification are disabled for these fields. This also discourages learning while passages are added, not just while answering. The dedicated Dictate button remains available if the keyboard hides its microphone in password mode. Keyboard flags cannot erase Gboard's existing learned data and third-party keyboards may ignore requests. Verify Gboard behavior on the phone.

Permission/access shortcut buttons are omitted from the alarm screen. Missing permissions are still listed, and enabling an alarm still checks them; grant missing access through Android Settings for Arise O Sleeper!. Sound settings and the sound preview remain available.

Each passage has its own **Quiet time** in seconds (default 60; range 1-3600). Set it when adding a passage, or edit it beside a saved passage and tap **Save quiet time**. Each check allows one quiet period of that duration, shared by the Quiet and Dictate buttons. Quiet time can be changed while alarms are enabled, but only when no routine is active. Closing the screen does not dismiss the alarm. Settings changes save immediately when no routine is active, even if a future alarm is enabled. During a routine (including quiet periods and follow-up waits), the Alarm settings button queues alterations with a 15-minute monotonic countdown. Reboot restarts this active wait. Pending changes cannot terminate an active wake-up routine. Once all checks finish, queued changes apply immediately and any remaining alteration wait is removed. Old pending changes from an idle routine also apply immediately. This is a separate alarm change queue, not a saved-password request. Adding passages is allowed while a future daily alarm is enabled. Removing passages still requires the alarm to be off. All library changes are blocked during an active routine.

Alarm configuration, passages, progress and the current challenge are committed together to device-protected preferences. Exact AlarmManager events and a foreground audio service support screen-off operation; boot broadcasts restore scheduling before first unlock. Follow-ups use elapsed time within a boot and wall time across reboot. Daily alarms follow the phone's local time zone. All daily times share the session count and verse library. Later alarms wait behind an active routine and are handled in scheduled order without dropping intermediate times. Editing the schedule or changing time zones recalculates future times. Existing saved alarms retain one daily time, three sessions and 60-second quiet periods until edited. Settings changes and answer submission reschedule the next event. A ringing challenge has a one-minute recovery alarm in case its process is lost.

## Validation

The alarm's existing JVM and instrumentation tests move with the feature into `ariseosleeper`, using the new package and independent clock/countdown helpers. Install Lock keeps its own countdown and watchdog tests. Run the build and test commands in the repository README for both apps. Actual alarm delivery, speech recognition and reboot behavior need device acceptance testing.

Validation on 2026-10-27: both debug APKs and both instrumentation APKs built successfully. All 268 JVM tests passed (240 Install Lock, 28 Arise O Sleeper!). All 18 alarm instrumentation tests passed on a temporary, read-only Pixel 7 emulator running API 37, covering the alarm screen, settings persistence, storage, migration of older alarm state, sessions, quiet times, warning delivery, overlapping schedules, and reboot-clock reconciliation. APK metadata confirms the new app's exact display name and separate launcher; DEX inspection confirms Install Lock contains no verse alarm classes and the alarm APK contains no Install Lock classes. No physical phone was changed. Real timed delivery with the screen locked, actual reboot, speech-provider behavior, and manufacturer-specific reliability still need phone acceptance testing.

- `VerseAlarmRulesTest`: normalization, bounded speech matching, passage selection, follow-up deadlines, custom quiet deadlines, session validation, multiple daily times, time zones and DST.
- `VerseAlarmStoreTest`: durable advancement, duplicate submissions, early follow-up rejection, per-passage quiet limits, custom session counts, settings migration, overlapping alarms, memory promotion, active-routine protection and reboot recovery. Run on an isolated test device; instrumentation temporarily replaces this feature's preferences and restores them afterward.
- On-device acceptance: a real timed alarm with screen locked, all checks, dictation round-trip, process recreation, reboot before first unlock, silent/DND settings and permission revocation. A build or unit-test pass does not establish OEM alarm delivery reliability.

The alarm cannot establish that someone is physically out of bed or awake, and cannot ring while the phone is powered off. The standalone app does not inherit Install Lock's device-owner privileges: normal force-stop, data clearing and uninstall remain available. Android alarm permissions, sound settings, and device behavior affect delivery. When Install Lock manages the same phone, its configured installation wait and app restrictions apply to this separate app as well.
